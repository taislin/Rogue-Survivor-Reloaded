About this port

Rogue Survivor is a 2012 C#/Windows Forms game by Jacques Ruiz (roguedjack). Rogue Survivor Reloaded is a browser port of it: the same game, rewritten in TypeScript against a canvas instead of a GDI surface.

Why it exists

The original needs Windows and the .NET 3.5 runtime, and its System.Drawing drawing code has no browser equivalent. Rather than rewrite the game, the port replaces the three things that cannot survive a browser and leaves the rules alone — so the behaviour you get is the behaviour the original had.

How the port works

The original draws straight to a GDI surface, blocks on WinForms message loops and reads Keys.D0-style key codes. All of that is replaced. The game rules, the map generators, the AI and the item and skill tables are a direct port, kept line-for-line comparable to the C#.

In the original In the port
IRogueUI web/src/engine/IRogueUI.ts — the rendering and input contract
WinForms canvas in RogueForm web/src/ui/CanvasUI.ts — Canvas 2D
Blocking UI_WaitKey / UI_PeekKey Promises fed by web/src/ui/InputHandler.ts
Application.DoEvents() busy-wait loops await plus the real DOM event loop
System.Drawing Point / Rect / Color in web/src/engine/
CSV resource files JSON tables in web/src/gameplay/data/
PNG sprites, MP3 audio Lossless WebP sprites, Ogg audio

Most methods in the engine carry a comment pointing at the C# method they came from, for example // C# HandleCredits — RogueGame.cs:2248. That is deliberate: it is what makes a regression traceable back to the original.

Running the game without a browser

Because everything reaches the screen through IRogueUI, a second implementation that simply drops every painting call and answers key presses locally lets the entire engine run headless. That is what the simulator and the test suite are built on: same generators, same AI, same turn loop, in Node.

This is not a convenience

A clean type-check and a clean build do not mean the port works. The first headless run found nine runtime bugs, two of them fatal, and none of them visible to the type-checker. If you change engine code, run the simulator.

Under the hood

Technology

  • TypeScript 5, strict mode
  • Vite 5 for the dev server and the bundle
  • Canvas 2D — no game framework, no UI framework
  • Web Audio API for music and sound
  • Vitest for the test suite
  • Express for the optional production server
  • Node 20 or newer

Display

  • 1366×768 (16:9), the original was 1024×768 (4:3)
  • 31 tiles across instead of 21 — the extra width went to the map
  • Two text sizes: the dense in-game HUD, and full-screen menus
  • Offscreen districts keep simulating without you
  • Installable as a PWA, and playable offline

Status

The port is at alpha 10.1, matching the original's version number. The game content is complete: there are no unported stubs left.

Known limitation Detail
No touch support Keyboard and mouse only. This is the last item outstanding on the porting plan.
Minimap does not record explored ground Ground you have seen is not marked as explored, so the minimap under-reports what you know. Known bug, tracked in the porting plan.
Death screenshots off by default The original wrote a file silently; in a browser that is a download prompt on every death. The option still exists.

About this website

Static HTML in docs/, served by GitHub Pages. No framework, no build step, no tracking. The manual page is generated from the original RS Manual.txt by docs/tools/build-manual.mjs, which reformats the text and does not rewrite a word of it. Every sprite on the site is the game's own artwork.
